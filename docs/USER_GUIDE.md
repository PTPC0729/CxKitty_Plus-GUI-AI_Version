# CxKitty 0.5.0 使用说明

本源码包和公开 Release 均不附带账号、配置、密钥或题库。程序无需 config.yml 即可启动；可在界面保存设置，或复制 config.example.yml 为 config.yml 后编辑。


### 多任务标签页

顶部的 **“＋ 新建页”**（`Ctrl+T`）可创建独立任务页，像浏览器一样切换、拖动排序、关闭。每页保留原来的“账号登录 / 课程任务 / 设置 / 结果与日志”四个功能页；可以分别选择不同课程，点击各页的“开始处理”同时运行。切换标签不会暂停后台任务；标签标题显示课程及运行、暂停、停止或错误状态，鼠标悬停可看完整名称和说明。

- 第一次启动时选择已有账号、扫码或密码登录。此后新页沿用**本次程序运行中最近一次成功手动登录或手动选择的账号**，并自动加载课程与章节；不会自动开始任务。新页复制会话，不共享 Cookie 对象或网络连接。
- 例如第一页登录 A，第二页自动沿用 A；在第二页手动登录 B 后，以后新建页沿用 B，第一页继续使用 A。切回旧页、自动继承、登录失败都不会改变继承来源；关闭来源页后仍可继承，直到退出程序。
- 每页的课程、章节起点、设置、AI 密钥输入、运行结果、日志、暂停和停止互相独立。同一账号可以处理不同课程；同一账号的同一课程（同一班级）只允许一个页运行，避免重复提交。自动选择课程和自动继续下一门时会跳过其他页正在处理的课程；手动选中重复课程时会显示提示。
- 在某页调整设置后，该页下次任务立即采用当前输入；点击**保存设置**还会将其保存为以后新建页和下次启动的默认设置。其他已打开页及已经启动的任务保持各自的设置。每个新页默认不复制另一个页尚未保存的设置。
- 点击标签的 **×** 或 `Ctrl+W` 关闭当前页：先停止该页后台任务，再移除标签；其他页继续运行。关闭主窗口会停止所有页并等待后台退出；关闭最后一个标签也会退出。`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换标签。
- 标签布局及各页临时输入不在退出后恢复；账号存档、已保存设置、AI 缓存、视频记录和运行日志继续保存在原来的外部文件中，格式兼容旧版。多页写入共用文件时会串行合并，避免丢失另一页记录。

0.5.0 使用项目中的 `xxt_helper.ico` 统一 EXE、窗口左上角和任务栏图标，打包后图标内置，不依赖原来电脑的绝对路径。二维码仍使用原来的整数像素缩放方式，与应用图标无关。

默认启动 PySide6 桌面界面，提供账号登录、课程章节、任务设置、结果与日志四个页面。登录后自动加载课程并从上到下选择第一门尚未完成、可访问的课程，选择课程后自动显示章节。网络请求和课程任务在后台运行，支持暂停、继续、停止、视频续接和继续未完成章节。

### 课程操作与起始章节

1. 登录后等待课程列表自动加载。程序核验课程进度并选择首个待完成课程；这一步只查询状态，不会自动提交课程任务。切换课程时会自动加载章节，快速切换时旧请求的结果会被丢弃。
2. 默认起点为“自动：从首个未完成章节开始”。点击“开始处理”后按章节顺序执行，自动跳过平台确认完成的章节和任务。
3. 要从中间开始，在“起始章节”下拉框选择一章，或选中章节行后点击“从选中章节开始”（也可双击章节行），再点击“开始处理”。选中大章目录会从其下属章节开始，并继续后面的章节。仅选中一行不会启动任务。
4. “继续未完成 / 重试”覆盖上次执行范围内的失败、中断、未处理及等待平台确认的章节。开始前重新核验平台状态，已经完成的部分自动跳过。
5. 可勾选“本课程全部完成后，继续后续未完成课程”。本课程获得平台完整确认后，程序从下一门课程开始顺序查找并继续；仍有失败或未完成任务时不会直接切换。默认关闭，保存设置后记住此选项。
6. “刷新课程”“刷新章节”保留为手动重新查询入口；正常登录和选课不需要点击。“在平台打开”用于检查暂未接入的阅读、投票等组件或课程开放状态，浏览器可能需要单独登录。

视频续播使用平台最新返回的位置，并将毫秒转换为秒。本地上报记录不会覆盖平台进度；旧版留下的错误结尾记录会自动忽略，无需手动删除文件。平台没有提供有效进度，或位置已到结尾却仍未完成时，从头重新播放；电脑休眠时间不会累计为播放时间。

0.4.2 修复视频上报持续返回 HTTP 403 的协议问题：使用任务页面提供的上报地址，兼容 `/mooc-ans/` 路径，并将 `courseId` 作为独立参数传递，避免编码后被吞进 `otherInfo`。打包自检已覆盖任务读取到视频上报的完整参数传递。

单个视频或任务的 HTTP 401/403 会触发独立的账号有效性查询。账号仍有效时，记录该资源的访问错误并继续其他任务；仅当账号验证接口明确确认失效时才要求重新登录。查询超时或接口异常不会被当成登录失效，也不会为了核验账号自动重发任务提交。

任务统计结合平台总数、完成数、未完成数与章节任务数量；目录显示子章节汇总，无任务点显示“— / 无任务点”，仅在信息不足时显示“未知 / 待核验”。任务完成后立即刷新，运行中会显示“处理中”“已暂停”“失败 · 可重试”等状态。阅读、投票等未接入组件会明确记录为“平台处理”，不伪报成功；程序目前自动处理文字单选、多选、判断题以及视频、文档任务。

```powershell
python -m pip install -r requirements.txt
python main.py
```

Windows 安装依赖后也可双击 `start.bat`。Python 支持 3.10～3.14；如使用 Poetry，请使用 Poetry 2.x，执行 `poetry install` 和 `poetry run python main.py`。

### AI 自动答题

在“设置”页将“题库类型”改为 **AI 自动答题**，填写接口 URL、API 密钥、模型名称，再点击“检查题库 / AI”。检查通过后点击“保存设置”，登录账号、选择课程并开始处理。默认策略是**全部使用 AI，取得有效选项后自动提交**，没有人工确认步骤，也不检查模型的正确率或置信度。

程序使用 **Chat Completions 兼容协议**：发送 `model`、`messages`、`stream: false`，读取 `choices[0].message.content`。支持提供此协议的云端服务或本地模型服务；网页聊天地址、仅支持其他协议的接口不能直接使用。

| AI 设置 | 作用 |
| --- | --- |
| 接口 URL | 可填写 `https://你的服务地址/v1` 或完整的 `https://你的服务地址/v1/chat/completions`。只填写域名时自动补 `/v1/chat/completions`；其他路径后自动补 `/chat/completions`。不会自动跟随重定向。 |
| API 密钥 | 以 Bearer 认证发送。输入框隐藏显示；无需认证的本地服务可留空。按接口地址独立保存，切换地址会载入该地址对应的密钥。 |
| 模型名称 | 填写服务商实际提供的模型 ID，不是模型网页地址。 |
| 答题策略 | “全部使用 AI”先查 AI 缓存，未命中才请求模型；“原题库优先”先查下方指定的 JSON、SQLite 或 REST 题库，未匹配、答案无法转换或题库不可用时再转 AI。 |
| 优先题库 | 仅在“原题库优先”时生效，对应配置栏会显示在上方的题库设置中。 |
| 请求超时 | 每次模型请求的读取超时，默认 90 秒。暂停会阻止后续处理；停止可立即退出等待，已发出的请求仍可能在服务器端完成。 |
| 失败后重试 | 默认额外重试 2 次。超时、限流、服务错误和无效答案格式会有限重试；密钥、权限、路径或参数错误会提示修正配置，避免对每道题重复发出无效请求。此重试不用于重发平台的测验提交。 |
| 输出 token 上限 | 默认 4096；限制模型生成量，推理模型可能需要提高。不是输入题干长度限制。 |
| 上限参数名称 | 多数兼容服务使用 `max_tokens`；需要 `max_completion_tokens` 的模型选择另一项。模型不支持参数时可在日志看到 HTTP 400 / 422 提示。 |
| 答案缓存 | 默认开启，同一接口、模型、题干、题型和选项组合直接复用答案。更换模型或选项变化后不会错误复用旧记录。关闭后不读写缓存。 |
| 缓存文件 | 默认 `ai_cache.json`，相对路径以数据目录为基准；可单独备份。缓存损坏时继续请求 AI，保留原文件并提示。最多保留 10000 条记录。 |

发送给模型的是当前题目的题干、题型和完整选项，不发送学习通 Cookie、手机号、密码或课程提交令牌。支持现有的**文字单选题、多选题、判断题**；目前没有增加图片题、填空题、简答题或课程考试支持。模型逐题返回答案，程序完成整份测验后自动提交，不把每道题单独提交给平台。

模型返回 JSON 选项、简单选项字母、明确的选项全文，以及判断题的 true / false 或“正确 / 错误”都可解析；允许模型在不确定时选择最可能的答案。只检查返回结果能否转换为题目中存在的选项。接口始终不可用、空答案或无效选项达到重试上限时，该测验会记录失败，其他课程任务继续；不凭空填写随机选项，也不提交缺题的试卷。

**密钥和缓存独立储存：**

- `config.yml` 保存服务地址、模型、策略、超时等非密钥设置，兼容以前的配置；旧配置自动补齐 AI 默认字段。
- `ai_credentials.json` 保存各接口的密钥，是本地明文 JSON。点击“保存设置”才持久保存；不保存设置也可在本次运行使用输入的密钥。密钥不写入日志，不内嵌进 EXE。
- 命令行 / Docker 可用环境变量 `CXKITTY_AI_API_KEY` 提供密钥；它优先于密钥文件。GUI 会载入该值，之后可在输入框中修改本次使用值。
- `ai_cache.json` 保存题目指纹及模型选项，不包含 API 密钥或登录会话。

“检查题库 / AI”会向填写的模型服务发送一道测试题，可能产生少量服务费用；程序的打包自检只连接本机模拟接口，不调用真实模型。正常运行时的请求费用取决于你配置的服务，缓存可以减少重复调用。

无 GUI 时可在原 `config.yml` 的 `searcher` 中增加以下内容，原有 JSON、SQLite、REST 配置继续保留：

```yaml
searcher:
  use: aiSearcher
  aiSearcher:
    url: https://你的服务地址/v1
    model: 你的模型ID
    strategy: ai_only        # ai_only / bank_first
    fallback: jsonFileSearcher
    timeout: 90
    retries: 2
    max_tokens: 4096
    token_parameter: max_tokens
    cache: true
    cache_path: ai_cache.json
```

### Windows 图形化打包工具

双击项目根目录的 **`start_packager.bat`** 打开专用打包界面；如果已有 **`CxKitty-Packager.exe`**，也可以直接双击它。打包工具与主程序是两个独立窗口。主程序仍由 `start.bat` 启动。

构建电脑需要 Windows、完整项目源码、Python 3.10～3.14；推荐使用 64 位 Python。生成的主程序包含 Python 和所需运行依赖，使用者无需另装 Python。EXE 面向构建时的 Windows 架构，不是 macOS / Linux 程序。

首次准备环境可执行：

```powershell
python -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-build.txt
.\start_packager.bat
```

工具自动优先选择项目中的 `.venv-build`，其次为 `.venv`。独立的打包工具 EXE 自带界面依赖，但**编译项目仍需要选择外部 Python 解释器**。没有源码或 Python 时不能仅靠打包工具 EXE 构建项目。

| 控件 | 用途及影响 |
| --- | --- |
| 项目目录 | 选择包含 `main.py`、`build_backend.py` 的完整项目。 |
| Python 解释器 | 选择用于编译的 `python.exe`，不要选 `pythonw.exe`；其位数决定产物架构。 |
| 输出位置 | 每次在这里创建带时间与随机标识的新发布目录，避免覆盖旧程序或数据。 |
| 程序名称 | EXE 文件名，不含 `.exe`；不改变程序内标题或功能。 |
| 单文件 EXE | 依赖内嵌在一个 EXE 内，每次启动先解压到临时目录，启动稍慢。 |
| 目录模式 | EXE 和 `_internal` 依赖目录一起使用，启动较快，必须整体复制。 |
| 程序图标 | 默认选中项目目录中的 `xxt_helper.ico`，留空也采用它。也可选择其他 `.ico`，同时改变主程序 EXE、窗口和任务栏图标；图标内置在成品中，无需额外复制，不影响二维码。更换项目目录时自动更新默认图标路径，手动选择的自定义图标保留。 |
| 携带当前配置 | 公开版默认不勾选；勾选后保留当前设置及额外配置字段；取消后使用默认配置，同时关闭数据复制选项。 |
| 复制本地题库及 AI 答案缓存 | 公开版默认不勾选；勾选后复制配置中存在的 JSON / SQLite 文件及启用的 AI 缓存到 `data/`，修改发布版中的相对路径。SQLite 使用只读连接备份，包含已提交的 WAL 数据。原文件不变。缺失题库会在日志提示，不会凭空补齐。 |
| 携带已有账号会话 | 默认不勾选；勾选后将配置指向的会话目录中的 JSON 原样复制到发布目录的 `session/`。含 Cookie 和可能保存的密码，请仅用于本人迁移。 |
| 携带 AI 密钥 | 默认不勾选。勾选后把密钥复制为发布目录中独立的 `ai_credentials.json`，仍不嵌入 EXE；只适合本人迁移。不勾选时需在发布版重新填写密钥或设置环境变量。 |
| 检查环境 | 检查 Python、依赖版本及关键二进制模块是否可导入，不自动安装。 |
| 安装 / 补齐依赖 | 联网执行所选 Python 的 pip，安装 `requirements-build.txt`，会调整这个 Python 环境中的依赖；推荐选虚拟环境。 |
| 开始打包 | 自动检查 → 构建 → 携带数据 → 启动实际 EXE 自检 → 写说明和清单。 |
| 取消 | 停止当前构建及子进程；不影响原项目、以前的发布目录。可能保留带 `BUILD-INCOMPLETE.txt` 的失败目录和日志。 |
| 打开输出目录 | 打开本次发布目录；尚未构建时打开填写的输出位置。 |
| 运行生成的 EXE | 仅在当前构建及实际 EXE 自检成功后可用。 |
| 导出当前日志 | 保存界面中的日志；完整构建日志另存于发布目录 `build-log.txt`。 |

正常流程：打开打包工具 → 确认项目与 Python → 检查环境，必要时补齐依赖 → 选择模式和携带数据 → 开始打包 → 等待“打包成功” → 运行 EXE。

发布目录内包含主程序、`config.yml`、所选题库、缓存、会话和密钥文件，以及 `build-info.json`、构建日志、使用说明和 `verification/` 自检报告。不会携带原项目的历史日志。自检只使用临时的模拟账号、题库和任务，以及本机模拟 AI HTTP 服务，不登录真实账号，不请求真实课程或模型接口。只有 EXE 内的 AI 请求、答案转换、自动提交与缓存流程也通过自检，才显示打包成功。

**EXE 与数据的关系：**单文件指程序及依赖装入一个 EXE；可变配置、账号、题库与日志仍保存在 EXE 外部。单独复制 EXE 可以用默认设置启动；要保留原设置和数据，应复制整个发布目录。发布配置的会话路径统一为 `session/`；取消题库复制时保留原题库路径，绝对路径或网络 REST 题库服务需要在目标电脑上继续可用。

数据默认相对于 EXE 所在目录，与启动时的工作目录无关，也不会写入单文件解压产生的临时目录。请放在有写入权限的文件夹；如需另存数据可用 `CxKitty.exe --data-dir "D:\CxKittyData"`，或环境变量 `CXKITTY_DATA_DIR`。该目录需自行放入要继续使用的配置和数据。Python 版也支持同一参数。

原终端入口仍可使用：

```powershell
# PowerShell 中等待窗口程序结束并保留交互控制台
Start-Process -FilePath .\CxKitty.exe -ArgumentList '--cli' -NoNewWindow -Wait
# 离线自检：报告写到指定路径，不修改真实账户和配置
.\CxKitty.exe --self-check .\verification\manual-check.json
```

更新时先关闭程序，单文件版只替换 EXE；目录版替换 EXE 和整套 `_internal`。保留自己正在使用的 `config.yml`、`session/`、题库、`ai_credentials.json`、AI 缓存和 `logs/`，不要拿新发布目录的默认配置覆盖存档。

也可使用与 GUI 完全相同的构建后端：

```powershell
.\.venv-build\Scripts\python.exe build_backend.py build --output dist --name CxKitty --mode onefile
# 目录模式 / 携带已有会话
.\.venv-build\Scripts\python.exe build_backend.py build --output dist --name CxKitty --mode onedir --sessions
# 本人迁移时可另外明确选择携带 AI 密钥（独立文件）
.\.venv-build\Scripts\python.exe build_backend.py build --output dist --name CxKitty --mode onefile --ai-keys
# 可选：重新生成打包工具自身的独立界面 EXE（输出到项目根目录）
.\.venv-build\Scripts\python.exe build_packager.py
```

打包复用原来的 GUI、终端和业务代码。自检验证 Qt 启动、配置/会话读写、JSON/SQLite/JSONPath、测验页面解析（包括字符串标识、前导零、编码题数及完整题目清单）、AI 请求与自动提交、AES、HTTPS 证书、二维码绘制和离线任务结果保存；登录、课程服务、模型和在线题库仍受网络及平台接口影响，与 Python 版一样。

使用顺序：在“账号登录”中选择原有会话或登录新账号 → 等待自动选课和加载章节（也可自行切换课程）→ 在“设置”中选择任务类型及题库 → 选择起点并开始处理。任务运行时设置暂不可编辑；未点击保存的设置也会用于本次任务，点击“保存设置”后写入原来的 `config.yml`。

二维码按完整黑白模块绘制，包含四个模块宽的白色静区；根据屏幕 DPI 使用整数物理像素缩放，不拉伸、不平滑插值。窗口宽高不一致时仍保持方形并居中。二维码失效、取消或登录完成后会清除；也可导出完整 PNG 原图。

### 数据兼容

- 继续使用原 `config.yml` 的字段和结构，补齐缺失的默认字段；不会在启动时覆盖配置。
- 继续读取 `session/*.json`，保留 `phone`、`puid`、`passwd`、`name`、`ck` 字段及额外字段。已有密码仍可用于重新登录；GUI 新登录默认只存会话，勾选保存密码时仍按旧格式明文保存。
- 兼容原 JSON 字典、SQLite 表字段及 REST API / JSONPath 题库配置。配置中的相对路径统一相对于数据目录（默认是源码目录或 EXE 所在目录）。
- 配置和会话采用原子写入。损坏的单个会话会被跳过并提示，原文件不会自动删除。
- 每次课程运行在 `logs/` 保存结果 JSON，支持界面导出；记录不包含密码、Cookie 或登录二维码链接。
- 视频上报记录独立保存在 `video_progress.json`，按账号、课程、班级和资源区分。上报记录不代表平台保存了同样的进度或确认完成，实际续播始终以平台最新返回的位置为准。打包默认不携带，勾选复制账号会话时一并复制；更新 EXE 时可保留此文件。

### 执行结果与边界

任务成功、失败、跳过分开记录；接口无任务、请求失败、未知状态不再混为一谈。程序最终重新核验章节完成状态，不会仅因为循环结束就显示“已通过”。已关闭的任务在请求、解析前过滤。

网络请求有连接及读取超时；只自动重试发送请求前的连接失败，不自动重发答题提交。暂停会阻止后续处理；停止可及时退出网络等待，迟到响应不会更新新任务或继续提交。已发送至服务器的请求无法撤回，重新开始前会核验平台状态。HTTP 400 / 422 只影响当前问题；明确的鉴权、路径或请求方式错误才阻断本轮后续 AI 请求。

视频支持小数倍速、精确结尾上报及有限失败次数。重新运行会跳过平台确认完成的章节，未完成视频按平台最新返回的播放位置继续；中断前尚未成功上报的少量进度可能需要重新处理。

章节测验开关现在按配置生效。**项目不附带题库**：默认题库不存在时，相关测验记录为失败，其他任务继续；也可选择 AI 自动答题，通过配置的模型服务获取答案。题目数量、提交参数或答案格式不完整时不会提交；不支持的题型同样会保留失败原因。平台页面和接口可能变化，遇到此类错误请查看结果页，而不是把任务跳过理解成完成。
